On each client device

The browser finds 33 body landmarks with MediaPipe; only these coordinates go to the node. The node turns them into 46 features per frame, classifies 1.6 s windows with its personal Bi-LSTM, and learns from the operator's corrections in batches of 16 windows, using replay and EWC so it does not forget.

On the aggregation server

The server never sees raw data. In each round it receives model weights from the clients, combines them weighted by data size, applies a FedAdam step, and measures every client's contribution: update share, alignment and exact Shapley value on a validation set.

How a federated round works

The same five steps are animated live on the admin console and on every client page.

Updates receivedEach client trains the global model locally with FedProx and uploads its weights wk.
Data weightspk = nk / N, so clients with more data count more.
Weighted sumΔ = Σ pk (wk − wt), the average update.
Server optimiserFedAdam turns Δ into a step using its momentum and variance.
New global modelSent back to every client; contributions and Shapley values are recorded.
